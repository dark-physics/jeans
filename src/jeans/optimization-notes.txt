# Performance optimization summary
# --------------------------------
# The nonspherical shape calculation was optimized to reduce repeated adaptive
# integrations and Python-level scalar loops.
#
# 1. Baryon angular moments
#    - compute_Mb now calculates the monopole and L=2 quadrupole of Phi_b
#      together using fixed Gauss-Legendre angular quadrature.
#    - Vectorized baryon potentials are evaluated over the full (r, theta)
#      grid in one call, with fallbacks for non-vectorized potentials.
#    - The quadrupole is cached on the resulting M_b callable and reused by
#      compute_log_q_baryon, avoiding a second set of angular integrations.
#
# 2. Vectorized profile functions
#    - M_b, log_q_baryon, q_iso, and related interpolation wrappers now handle
#      arrays with NumPy masks instead of recursive scalar calls.
#
# 3. q_iso integration
#    - The F(r) and H(r) integrals are evaluated directly on the existing
#      radial grid using cumulative quadrature.
#    - This replaces two adaptive solve_ivp calls during every q_iso iteration.
#
# 4. q_eff evaluation
#    - Numeric q0 values remain numeric, allowing compute_q_iso to use its
#      simpler constant-shape branch.
#    - q_eff is sampled on a logarithmic radial grid and interpolated during
#      spheroidal-grid construction.
#    - Values outside the interpolation range still use the direct expression,
#      preserving the behavior of radius-dependent q0 functions.
#
# 5. Spheroidal-radius grid
#    - All (r, theta) grid points are solved simultaneously using NumPy arrays.
#    - q(r_sph) is evaluated once per iteration rather than twice per point.
#    - The damping schedule was corrected so it does not decrease immediately
#      or become zero or negative.
#
# 6. NumPy scalar compatibility
#    - Scalar results from the spheroidal interpolator are normalized to true
#      scalars.
#    - The spherical baryon-potential wrapper now correctly handles scalar,
#      0D, 1D, and multidimensional radius inputs.
#
# In a representative Miyamoto-Nagai test, total squashed-profile construction
# decreased from approximately 19 seconds to approximately 2 seconds. The new
# q_eff agreed with the previous adaptive implementation to better than 0.07%
# across the tested radial range.

# Rotation-curve performance optimization summary
# -----------------------------------------------
# The L=0 and L=2 dark-matter rotation-curve calculations were optimized to
# reduce repeated angular integrations and radial quadrature.
#
# 1. Shared density multipole calculation
#    - The L=0 monopole rho_00(r) and L=2 quadrupole rho_20(r) are calculated
#      together from one shared angular density table.
#    - Fixed 64-node Gauss-Legendre quadrature replaces independent adaptive
#      angular integrations for the primary L=0 and L=2 path.
#    - At each radius, rho(r, theta) is evaluated once at the angular nodes and
#      reused when projecting onto both spherical harmonics.
#    - Higher multipoles retain the previous adaptive implementation.
#
# 2. Per-profile caching
#    - The shared density-moment table is cached on the profile object.
#    - Completed rho_LM interpolation functions are cached using their
#      L, M, spline order, radial-grid size, and angular-grid size.
#    - Repeated calls to V(), Vsq(), or Vsq_dm() on the same profile therefore
#      reuse the existing multipole splines instead of rebuilding them.
#
# 3. L>0 exterior radial integration
#    - The exterior radial contribution H(r) is now calculated with one
#      cumulative adaptive solve evaluated at all requested radii.
#    - This replaces separate quadrature calls between each pair of requested
#      radii followed by repeated summation of the remaining intervals.
#    - The existing large-radius tail calculation is retained.
#
# 4. Numerical agreement
#    - The shared angular-moment implementation agreed with the previous
#      adaptive calculation to approximately 1.2e-6 in relative V_dm^2.
#    - The consolidated radial integration agreed with the previous
#      implementation to approximately 4.0e-6 in relative V_dm^2.
#    - Repeated velocity evaluations returned identical results.
#
# 5. Representative performance
#    - In the test profile, the first Vsq_dm(r, Lmax=2) evaluation decreased
#      from approximately 20 seconds to approximately 2 seconds.
#    - Once the per-profile cache was populated, a repeated evaluation took
#      approximately 0.16 seconds.
#
# These optimizations preserve the public rotation-curve interface and retain
# the previous fallback behavior for multipoles other than L=0 and L=2.
